# A Unified Model for Cross-Domain Clone Detection via Model Merging

Replication package for the paper "A Unified Model for Cross-Domain Clone
Detection via Model Merging."

The package reproduces the full study: fine-tuning specialist code encoders,
merging them into a single cross-domain clone detector with several
parameter-level and architecture-level methods (including WUDI-Merging and
PCB-Merging), evaluating on three clone-detection benchmarks, and comparing
against large-language-model baselines.

## What the study shows

A code encoder fine-tuned on one clone benchmark is strong in-domain but weaker
on other domains and languages. The study combines independently fine-tuned
specialists, without any additional training, into one model that performs well
across domains.

The pipeline has four stages:

1. Fine-tune `CodeBERT`, `GraphCodeBERT`, and `UniXcoder` specialists on
   BigCloneBench and CLCDSA.
2. Merge the specialists with parameter merging (weighted averaging, TIES,
   DARE-TIES, WUDI-Merging, PCB-Merging) and architecture merging
   (layer-composition search).
3. Evaluate every specialist and merged model on BigCloneBench (BCB), CLCDSA,
   and GPTCloneBench.
4. Compare against a multi-task "train on all data" model and zero-shot
   large-language-model baselines (Qwen2.5-Coder-7B-Instruct and
   DeepSeek-Coder-6.7B-Instruct).

## Verify the reported numbers without re-running anything

The evaluation outputs for every model are included under
`clonemerging/evaluation/results/` as JSON files (accuracy, precision, recall,
and F1), named `<model>_<benchmark>.json`. The LLM baseline outputs are in
`llm_baseline/`. You can inspect these directly to check the numbers reported in
the paper. Full reproduction (below) requires GPUs and is optional.

## Setup

Python 3.10 or newer with a CUDA-capable GPU is recommended.

```bash
conda create -n clonemerge python=3.10
conda activate clonemerge
pip install -r requirements.txt
```

Run all commands from the package root.

## Data

The study uses three public clone-detection benchmarks: BigCloneBench (via
CodeXGLUE), CLCDSA (which also provides the cross-language clones), and
GPTCloneBench. They are not redistributed here. See [docs/DATA.md](docs/DATA.md)
for download links and the expected layout under `data/`.

## Reproduce the study

Fine-tuned specialists and merged checkpoints are large and are not shipped in
this package; they are regenerated by the steps below and written under
`checkpoints/`. See [docs/MODELS.md](docs/MODELS.md) for the complete list.

### 1. Fine-tune the specialists

```bash
python clonemerging/training/finetune.py \
    --model_name microsoft/codebert-base \
    --dataset_type bcb \
    --output_dir checkpoints/codebert_bcb \
    --epochs 5 --batch_size 32 --lr 2e-5 --seed 42
```

Repeat for each base model and benchmark (see [docs/MODELS.md](docs/MODELS.md)).
The multi-task baseline uses `clonemerging/training/finetune_combined.py`.

### 2. Merge

Parameter merging (weighted averaging, TIES, DARE-TIES):

```bash
python clonemerging/merging/parameter_merging.py \
    --base_model microsoft/codebert-base \
    --checkpoints codebert_bcb codebert_clcdsa \
    --checkpoint_root checkpoints \
    --base_models microsoft/codebert-base microsoft/codebert-base \
    --weights 1.0 1.0 \
    --output_dir checkpoints/merged_dare_ties
```

WUDI-Merging:

```bash
python clonemerging/merging/wudi_merging.py \
    --base_model microsoft/codebert-base \
    --checkpoints codebert_bcb codebert_clcdsa \
    --checkpoint_root checkpoints \
    --base_models microsoft/codebert-base microsoft/codebert-base \
    --weights 1.0 1.0 \
    --num_steps 300 --lr 1e-5 --seed 42 \
    --output_dir checkpoints/merged_codebert_wudi
```

PCB-Merging:

```bash
python clonemerging/merging/pcb_merging.py \
    --base_model microsoft/codebert-base \
    --checkpoints codebert_bcb codebert_clcdsa \
    --checkpoint_root checkpoints \
    --base_models microsoft/codebert-base microsoft/codebert-base \
    --weights 1.0 1.0 \
    --drop_rate 0.1 --intra_scale 1.0 --seed 42 \
    --output_dir checkpoints/merged_codebert_pcb
```

Architecture merging (layer-composition search):

```bash
python clonemerging/merging/architecture_merging.py \
    --checkpoints codebert_bcb graphcodebert_bcb \
    --base_models microsoft/codebert-base microsoft/graphcodebert-base \
    --checkpoint_root checkpoints \
    --output_dir checkpoints/franken_greedy
```

Run any script with `--help` for the complete option list.

### 3. Evaluate

```bash
python clonemerging/evaluation/evaluate_models.py \
    --checkpoint_dir checkpoints/merged_codebert_wudi \
    --dataset_type bcb \
    --output_file clonemerging/evaluation/results/merged_codebert_wudi_bcb.json \
    --batch_size 64
```

`--dataset_type` accepts `bcb`, `clcdsa`, or `gptclonebench`.

The `scripts/` directory contains end-to-end runners that reproduce the full set
of WUDI and PCB merges and evaluations across seeds and GPUs:

```bash
bash scripts/run_wudi_experiments_parallel.sh      # produce WUDI merged checkpoints
bash scripts/run_wudi_eval_parallel.sh             # evaluate them on all benchmarks
bash scripts/run_crossbase_wudi_extra_seeds.sh     # additional cross-base seeds
bash scripts/run_pcb_experiments_parallel.sh       # produce PCB merged checkpoints
bash scripts/run_pcb_eval_parallel.sh              # evaluate them on all benchmarks
```

### 4. Large-language-model baselines

Zero-shot Qwen2.5-Coder-7B-Instruct on GPTCloneBench:

```bash
python llm_baseline/eval_qwen_gptclonebench.py --pilot-only     # quick check
python llm_baseline/eval_qwen_gptclonebench.py                  # full run
```

`llm_baseline/qwen_output/metrics.json` and
`llm_baseline/qwen_output/predictions.jsonl` hold the outputs reported in the
paper.

Zero-shot DeepSeek-Coder-6.7B-Instruct on GPTCloneBench:

```bash
python llm_baseline/eval_deepseek_gptclonebench.py --pilot-only     # quick check
python llm_baseline/eval_deepseek_gptclonebench.py --batch-size 16  # full run
```

`llm_baseline/deepseek_output/metrics.json` and
`llm_baseline/deepseek_output/predictions.jsonl` hold the outputs reported in the
paper.

**Prompt.** Each code pair is presented to the model with a fixed system message
and user template. `{code1}` and `{code2}` are replaced with the two snippets
(truncated proportionally if the pair exceeds the model context).

System message:

```
You are an expert software engineer specializing in code clone detection.
```

User message:

```
Determine if the following two code snippets are SEMANTIC CLONES - that is,
whether they implement the same functionality, even if they look syntactically
different (different variable names, control structures, or implementation
strategies).

Code Snippet 1:
{code1}

Code Snippet 2:
{code2}

Are these two snippets semantic clones (functionally equivalent)?
Answer with exactly one word: "Yes" or "No".

Answer:
```

The model is decoded greedily (no sampling, up to 10 new tokens). A response is
scored as a clone (label 1) when it begins with "yes" after stripping surrounding
punctuation, and as a non-clone (label 0) otherwise.
